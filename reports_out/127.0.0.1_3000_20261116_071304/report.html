12. Scan limitations

  • Point-in-time, unauthenticated black-box assessment; authenticated areas, session handling after login and business logic were not tested.
  • Automated scanners produce false positives and false negatives; every finding classified as Potential or Unverified requires manual validation.
  • No exploitation, credential extraction, data modification, file upload, brute-force or denial-of-service testing was performed.
  • Only approved hosts and ports were contacted; redirects to unapproved destinations were not followed.
  • Wordlist-based discovery cannot prove absence of content; JavaScript-rendered routes and authenticated API endpoints were not enumerated.
  • OWASP Top 10 mapping is indicative. It does not establish compliance or non-compliance with any standard.
  • CVSS scores are provided only where the evidence supports a defensible vector; all other findings are intentionally not scored.
  • Nikto manages its own TLS handling; DOXA cannot enforce certificate validation inside Nikto, Nuclei or WhatWeb.
  • Nuclei out-of-band (OAST) templates were disabled; blind SSRF/injection checks that need a callback server were not run (use --oast to enable).
  • Module tls skipped: no HTTPS endpoint detected
  • Module gobuster failed: gobuster exit 1, no results; see logs/gobuster.log
  • Module params skipped: not part of the 'standard' profile
